# 用户确认完成后的资源收尾

本流程只在用户明确确认整个会话完成时执行。把“完成了”放在条件句、引用或规则讨论中，不算确认；完成一部分也不触发。只评估当前会话，不扫描历史会话或其他任务。

## 确认对象

- **绑定 worktree**：优先用 `list_artifacts` 获取当前会话实际附加的 worktree。没有附件就明确报告未发现绑定项，不把当前 cwd、主仓库或其他 Git worktree 当成本会话的临时目录。工具不可用则报告未核实。
- **额外生成物**：从本会话已有的文件写入、工具返回、资源链接和交付记录中确认文档、页面、报告、截图、临时副本等的精确路径或资源 ID。必要时仅补读本会话记录；不递归扫描用户目录、云盘或其他会话。不知道归属就保留并注明。

## 判断保留、归档或删除

| 对象与现状 | 默认建议 |
| --- | --- |
| 正式交付、已发布或共享页面、仍被引用的文档 | 保留；用户要求时再通过对应应用流程处理 |
| 全局已安装技能的源、运行时依赖、主仓库和原有文件 | 保留，不因当前会话结束而清理 |
| 有复查价值但不再活跃的会话专属资料 | 建议归档，先确认可恢复位置和引用影响 |
| 不再使用的任务 worktree，成果已可靠保存 | 优先建议可恢复归档，而非直接删除 |
| 确认属于本会话、无引用且无保留价值的临时副本 | 可建议删除，列出具体对象和理由 |
| 归属、使用情况、保存状态或可恢复性不明 | 保留并说明待核实项 |

评估 worktree 前，核对真实路径、Git common dir、分支与当前任务归属，以及未提交、未推送、未跟踪和被忽略的内容。不要只因目录名相似、MR 已创建或 `git status` 干净就判断可以清理。存在未保存成果、其他会话仍在使用、共享用途、主工作区或工具保护时保留。

未提交或未推送的内容不能被当成已经交付保存，默认保留。若用户已经授权可恢复归档，且受管工具能够完整保存这些改动、未推送提交和所需文件，核实 ignored 等未覆盖内容已另行保全后，可以按授权归档；不要求为了归档先发布未授权的代码，也不能直接删除。

引用判断以本会话已知用途和对象自身可见的引用、共享信息为限；不为证明“无引用”扫描全局。未检查或缺少证据不等于无引用，不确定的临时截图、草稿仍建议保留。

## 处置与回报

用户说“完成了”本身只授权本次盘点，不自动授权删除、移动、归档、撤销发布或关闭会话。先形成具体清单：对象的路径或链接、建议动作、依据，以及未保存内容或其他待核实事实。没有额外资源时简短说明即可，不制造待办。

有与对象、动作和条件匹配的既有授权，就继续执行，不重复请求许可。没有授权时只给建议；确需用户决定才能执行某项处置时，再针对已经核实的具体对象询问。检查和建议不能被表述为“已删除”或“已归档”。

实际处置使用对应应用和工具。由 `create_worktree` 创建并绑定的受管理工作区，使用 `archive_worktree`，传入 `list_artifacts` 返回的精确标识；它保存可恢复快照，但需要单独保全仍有用的 ignored 文件，并遵守共享、保护、子模块等限制。其他 worktree 按所属项目流程处理，不绕过工具限制；不使用强制移除、`reset`、`clean` 或 `prune` 掩盖残留。文档、页面按对应应用规则处理，权限不足或归属不明时保留。

用户确认的会话完成状态，与可选清理是否决定分开报告。可选清理待定不阻止 `complete`；若清理本身也是已授权的必需工作，按实际执行情况说明进展。不要为了避免清理而把未完成工作说成已完成，也不要自动归档聊天。

同一次完成确认只评估一次；只有新增资源、处置失败或用户要求变化时再更新相关项，不在每轮重复盘点。
